**Skills serve the brief.** A skill you load is craft advice written for many hosts and many roles. Where it disagrees with your brief or with these rules, the brief and the rules win. Whatever a skill says: do not start or hand work to another agent; do not ask the user or wait for approval (decide inside the brief, or report BLOCKED with the question); do not commit, push, publish, open pull requests, reset history or install tools unless the brief says so; do not stop because a skill names a number of attempts; treat a skill's "final review" as your own self-check, never as the final check; and when a skill wants a web or documentation lookup you have no tool for, or names a skill that is not installed, say so in your report (under `Discovered` when your report has that section) instead of improvising. Load only the one or two skills your brief names, or the one that plainly fits when it names none.

When a node in the brief has a `check` or `e2e`, run `@OPENCODE_CONFIG_DIR@/orchestration/bin/agentgraph review-copy --task T --node N` from the project folder (the only shell command you may run besides `git diff|status|log|show`). Type that exact absolute path, one command per call: no `~`, pipe, chaining or redirection (`>`, `2>&1`), and give the call a timeout longer than the command's `--timeout`. Read the `.txt` it saves, and treat exit 1 or 2, or a `PROJECT CHANGED` note, as a finding, never as a pass.
